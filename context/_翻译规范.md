## 🔞 最高优先级：一律非和谐版（`bonus == True`），和谐版永不采用

> 用户 2026-09-16 拍板。**本条优先级高于下面所有铁律。**

游戏用 `bonus == True` 开关切换两套内容：**bonus 分支 = 非和谐原版**，配对的 `else` = 作者为过审改写的**和谐版**。
我们**只保留非和谐版，和谐版永远别管**。

### 判断方法

**1. 标题**（`游戏文本/screens.rpy` 画廊）

```renpy
if <已解锁>:
    if bonus == True:  textbutton _("真名 {b}✓{/b}") → Replay(label)    ← 非和谐
    else:              textbutton _("和谐名 {b}✓{/b}") → Replay(label)  ← 和谐
elif bonus == True:    text _("真名")       ← 非和谐（未解锁分支）
else:                  text _("和谐名")     ← 和谐
```

- ⚠️ 外层的 `if <已解锁>: ... else: text(未解锁)` 与 bonus 无关，**那个 else 不算和谐版**。
- 唯一真源 `context/_official_names.json`：`name` = 非和谐真名，`alt` = 和谐名（仅留档）。
- 全库**只有 23 条**存在双名，清单见 `context/_screens_bonus.json`（`real` / `cens` 两字段）。
- 反直觉的一条：`ayanedorm20` 真名是**短的** `Still Young`，
  "Still Young, But Old Enough To Legally Consent" 那半句正是过审加的免责语。
- 旧提取器"按出现顺序取最后一个候选"必然抓到 else 的和谐名——**这是此前漏检的根因，已修**。

**2. 正文**（`游戏文本/*.rpy` 事件脚本，`if bonus == True:` 共 3169 处）

- **只加不换**（无 else）：bonus 下**多出**的一段台词 → 属非和谐版，**必须翻**
  （已确认这类台词现有提取流程已正常收录）。
- **二选一**（`if bonus: jump xxxX` / `else: <和谐收尾>`）：**`xxxX` 才是完整版**，
  非 x 的 `xxx` 多半只是几行空壳 + 一句 jump。判定 = 源码里 `^label <name>x:`（共 147 个）。

### 处置规则

1. 标题一律用 `name`（非和谐真名）。**任何地方发现和谐名都要改回真名**——
   `事件英文标题对照表.md/.html`、`guide.html`、以及已填的 `title_zh` 一视同仁。
2. 正文翻 `xxxX`（非和谐完整版）；**非 x 空壳不翻、不计入进度、不建骨架**。
3. **和谐版文本禁止进入译文**，也不要"顺手把和谐版也翻一遍"或同时保留双版本。
4. 工具链：`_merge_names2.py`（已按 bonus 分支取值）、`_screens_bonus.py`（诊断双名）、
   `_extract_x_events.py`（提取 x 版骨架，147 件已并入 `events/`，副本 `events_x/`）、
   `_fix_md_titles.py` / `_fix_guide_titles.py`（把和谐名回填成真名）。
5. **范围封边（用户 2026-09-16 拍板）**：
   - 那 123 件「非 x 兄弟版缺失」的事件**不在翻译范围内**——不提取、不建骨架、不计进度，别再提。
   - 147 件 x 版**不进 `guide.html`**（画廊本就没有它们的条目，不显示就不显示），
     译者直接读 `context/events/<label>x.json` 即可。
