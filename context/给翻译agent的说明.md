# 任务：给 LIL 导航站做中英翻译（请通读完再动手）

你好。我在给一个《Lessons in Love》(LIL) 视觉小说的事件导航网页做「中文 / 英文 / 中英对照」三语言切换。翻译工作交给你，请严格按下面的规则来。

## 工作目录

`C:\Users\anke\Desktop\LIL\分析\context\`

先读 `README.md` 和 `全量方案.md` 了解全局。你的产出**只写 JSON 文件**，不要碰任何 html / py。

## 硬性约定：路径/文件名一律用英文，中文只进文件内容

**所有目录名、文件名必须用英文（或事件 label 原名），绝对禁止用中文命名。** 中文只允许出现在 JSON 的「内容」（value）里，绝不出现在路径或文件名里。

- 目录用英文：`content/`、`ui/`、`assets/`
- 文件名用 label 原名（本身就是英文）：`chikachristmalloween2.json`、`beachsevenami1.json`
- ❌ 不要建 `学校事件.json`、`艾米线.json` 这类中文文件名

原因：中文路径在 URL 里会被百分号编码（`%E6%B8%B8…`），跨系统/浏览器/GitHub Pages 处理不一致时可能 404 打不开，调试也麻烦。英文路径零风险、零速度损耗。事件 label 本来就是英文，照用即可，不用翻译文件名。

## 翻译方向（重要，别搞反）

这个站点有两种文案，翻译方向**相反**：

1. **UI 界面文案 = 中 → 英**。原始文案是中文（按钮、标题、提示语），你要补**英文**。
2. **对话正文 = 英 → 中**。原始文案是英文（游戏对白），你要补**中文**。

## 第一步：先做 UI 文案（量小，优先）

填这 4 个文件，把每个中文词条的英文补上：

- `ui/zh-en.json` —— 界面按钮、标题、提示（约 31 条，已有一部分示例，请补全/校对）
- `speakers/zh-en.json` —— 说话人名
- `cats/zh-en.json` —— 分类名
- `versions/zh-en.json` —— 版本相关文案

格式是严格的 JSON（UTF-8，**禁止写注释**）：

```json
{
  "中文词条": "English Translation"
}
```

规则：
- **key（中文）一个字都不许改**，含标点、空格、全角符号。你只填 value（英文）。
- 不需要翻的（纯版本号、已是英文的）留空字符串 `""`，或干脆不写那个 key。
- 翻完先自查 JSON 合法性（能用 `json.load` 解析、不报错）再交付。

## 第二步：对话正文（量大，增量进行，不急着一次做完）

`events/` 目录下每个事件一个 `{label}.json`，**英 → 中逐句对照**：

```json
{
  "label": "chikachristmalloween2",
  "title_zh": "事件标题的中文译名",
  "lines": [
    { "en": "English original line.", "zh": "中文译文。" },
    { "en": "Another line...", "zh": "" }

```

规则：
- `lines[].en` 是英文原句，**必须与源文逐字符一致**（它是对齐锚点，改了就对不上）。
- `lines[].zh` 填中文译文；没翻的留 `""`。
- 一次翻一部分就行——**翻好哪些交哪些**，我这边增量整合，不用等全部翻完。
- 建议从 `start` 或 Ami 角色线（`ami*` 开头的事件）开始，先翻几个让我验证质量，再铺开。

## 翻译风格要求

1. 保留原文的语气、换行、角色口癖（Chika 活泼、Touka 克制、Sekai 旁白冷静克制）。
2. 双关、梗、专有名词（Sekai、pareidolia、ELATION PROTOCOL 等）尽量直译并保持全文一致；拿不准就保留原词，不要硬造。
3. 严禁自由发挥、严禁编造源文没有的内容。所有译文必须严格锚定原文。
4. 拿不准的句子，宁可留 `""` 标「待翻」，也不要瞎翻。
