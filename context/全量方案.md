# LIL guide.html 三语化 — 全量方案（蓝图）

> 状态：**框架已定 + demo 可跑**（`guide_bilingual.html`，用 start 事件真实独白演示）。
> 本文档说明：为什么全量不能单文件、最终架构长什么样、分几步落地。

## 一、为什么全量不能塞进一个文件

| 项 | 现状 | 加三语后（估算） |
|---|---|---|
| guide.html 体积 | 58 MB | **150~200 MB**（对照模式要同时存英文+中文正文） |
| GitHub Pages 单文件上限 | — | **100 MB**，超了会被拒 |
| 浏览器加载 | 已偏慢 | 单文件 200MB 会明显卡顿 |

**结论：全量必须改成「骨架 + 按需加载翻译」**，不能继续走单文件路线。

## 二、最终架构（全量落地时）

```
guide.html                      ← 瘦身骨架：导航逻辑 + UI + 事件元数据（不含正文译文）
assets/
  ui.{zh,en}.js                 ← UI 文案（小，直接内嵌或首屏加载）
  content/
    {label}.json                ← 每个事件的正文逐句对照，点进该事件时才 fetch 加载
```

- **打开主页**：只载骨架 + UI，秒开。
- **点进某事件**：才 fetch 那个事件的 `{label}.json`（几 KB~几十 KB），注入逐句槽位。
- 三模式切换按钮逻辑与 demo 完全一致，只是数据源从「内嵌」变「按需 fetch」。

> demo（`guide_bilingual.html`）为了单文件可直接预览，把数据内嵌了；全量时换成上面的按需加载即可，**按钮与渲染逻辑 100% 复用**。

## 三、逐句对照槽位（核心机制，demo 已实现）

正文每一句渲染成：

```html
<span class="ln [narr] [no-zh]">
  <span class="en">[<span class="spk">Sekai</span>]English line</span>
  <span class="zh">中文译文</span>
</span>
```

三模式用 `body[data-lang]` + CSS 控制显隐，**零 JS 重排**，切换极快：

| 模式 | `.en` | `.zh` |
|---|---|---|
| `zh` 中文 | 隐藏 | 显示（空则回退显英文） |
| `en` 英文 | 显示 | 隐藏 |
| `bi` 对照 | 显示（上） | 显示（下） |

- `no-zh` 标记未翻译句 → 中文/对照模式下自动回退显示英文，不留空白。
- 记忆：`localStorage.lil_lang` 存上次选择，默认中文。
